## Quick Start

### 1. Environment Setup

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

**Python version:** 3.10 or higher is required.  
**GPU:** Optional for training. CPU-only is fully supported (and required at inference).

### 2. Place Data Files

```
data/taxonomy_v1.json
data/train.csv      (columns: intent, utterance)
data/dev.csv        (columns: intent, utterance)
data/test.csv       (columns: id, utterance)
```

### 3. Run the Pipeline (in order)

```bash
# Phase 1 + 2: data cleaning, training, checkpoint
python -m train

# Phase 3: ONNX export, calibration, Mahalanobis fitting, dev analysis
python -m eval

# Phase 4: test inference + submission CSV
python -m predict
```

Each script logs to both stdout and a file in `logs/`.  
The full pipeline takes approximately:
- `train.py` : 30–90 minutes (CPU), 10–20 minutes (GPU with CUDA)
- `eval.py`  : 5–10 minutes (CPU)
- `predict.py`: 2–5 minutes (CPU, 3k test samples)

## Configuration

All tunable values live in **`config.py`**. The most important ones:

| Parameter | Default | Effect |
|---|---|---|
| `ENCODER_MODEL_NAME` | `BAAI/bge-small-en-v1.5` | Sentence encoder backbone |
| `BATCH_SIZE` | 64 | Reduce to 32 if OOM |
| `NUM_EPOCHS` | 10 | Stopped by early stopping |
| `LAMBDA_INFONCE` | 0.3 | Weight of InfoNCE geometry loss |
| `LAMBDA_CE` | 0.7 | Weight of cross-entropy boundary loss |
| `TAXONOMY_ANCHOR_WEIGHT` | 5 | Replication weight for taxonomy examples |
| `CONFIDENCE_GAP_DELTA` | 0.15 | Gap threshold for cross-encoder trigger |
| `SUBMITTER_NAME` | `"candidate"` | **Change this** before submitting |

To change the submitter name before generating the submission:

```python
# In config.py:
SUBMITTER_NAME = "your_name"
```

### `train.py` — Phase 1 (Data Engine) + Phase 2 (Training)

**Key design decisions:**

**Zero-example intent injection**  
`missing_item` and `wrong_item` have no examples in `taxonomy_v1.json`.  
`load_and_expand_taxonomy()` injects 12 canonical examples each, derived from  
the README's hidden-label rules, before any model sees the data.

**Cleanlab Confident Learning**  
`run_cleanlab()` runs 5-fold cross-validated logistic regression on TF-IDF  
features, collects out-of-fold predicted probabilities, and uses  
`cleanlab.filter.find_label_issues()` to detect mislabelled rows.  
TF-IDF is used (not the neural encoder) for speed; Cleanlab only needs  
rough probability estimates, not perfect ones.

**Taxonomy anchoring**  
Each taxonomy example is replicated 5× in the training corpus so that  
even if Cleanlab misses some noisy rows, decision boundaries cannot drift  
far from the human-verified intent definitions.

**Joint loss**  
`L = 0.3 · InfoNCE + 0.7 · CrossEntropy`  
InfoNCE builds clean cluster geometry; CE draws explicit hyperplane  
boundaries. Label smoothing (0.05) on CE reduces overconfidence on  
silver-labelled samples.

**Layer freezing**  
The bottom 6 of 12 BGE transformer layers are frozen. This reduces the  
risk of overfitting on the relatively small QuickCart training set while  
still allowing the upper layers (more task-specific) to adapt.

**Outputs:**
- `data/cleaned_train.csv` — Cleanlab-filtered training set
- `results/noise_report.csv` — Per-class noise rates
- `models/best_checkpoint.pt` — Best dev Macro-F1 checkpoint

### `eval.py` — Phase 3 (Export + Calibration) + Dev Analysis

**ONNX export**  
`export_to_onnx()` traces the full encoder+head graph with dynamic sequence  
length. ONNX Runtime reduces per-sample latency from ~40 ms (PyTorch CPU)  
to ~8 ms by fusing operators and eliminating Python overhead.

**Temperature scaling**  
`fit_temperature()` minimises NLL on dev.csv by sweeping T* in [0.1, 10.0].  
T* > 1 softens overconfident probabilities, making the OOS threshold  
more reliable.

**OOS threshold tuning**  
`tune_oos_threshold()` sweeps θ from 0.20 to 0.80 and picks the value  
that maximises the out_of_scope F1 score on dev.

**Mahalanobis fitting**  
`fit_mahalanobis()` uses `sklearn.covariance.LedoitWolf` to estimate a  
shared precision matrix on all cleaned training embeddings.  
Ledoit-Wolf adds an analytically optimal shrinkage regulariser that keeps  
the 384×384 covariance matrix invertible even when samples per class < 384.

**Outputs:**
- `models/model.onnx`
- `models/calibration_params.json` (T*, θ, δ, τ, label map)
- `models/mahal_params.pkl` (centroids, precision, τ)
- `results/eval_dev.json` (full dev metrics)
- `results/per_class_metrics.csv`
- `results/confusion_matrix.csv` + `confusion_matrix.png`
- `results/oos_threshold_sweep.csv`
- `results/cross_encoder_trigger_rate.csv`

### `predict.py` — Phase 4 (Inference + Submission)

**Inference pipeline per message (in order):**

```
1. preprocess()           Unicode NFKC, lowercase, URL removal
2. ONNX forward pass      tokenise → logits + embedding (~8–12 ms)
3. Temperature scale      logits / T* → softmax probabilities
4. OOS check              max_prob < θ → out_of_scope (skip 5–6)
5. Gap check              gap < δ → cross-encoder rerank top-3 (~30 ms extra)
6. Mahalanobis check      dist(v, centroid_c*) > τ → OOD flag
```

**Cross-encoder mode**  
Set `use_cross_encoder=False` in `IntentPredictor` to stay always under  
15 ms (bi-encoder only). The write-up discusses the accuracy trade-off.

**Outputs:**
- `submissions/candidate_predictions.csv` (id, intent)
- `results/test_latency_report.json`

## Latency Budget

| Path | Measured (dev laptop, 4 cores) | Estimate (prod 4-core / 15 GB) |
|---|---|---|
| Preprocess | < 0.5 ms | < 0.5 ms |
| ONNX tokenise + encode | ~8 ms | ~10–12 ms |
| Temp scale + OOS check | < 0.1 ms | < 0.1 ms |
| Mahalanobis distance | < 0.2 ms | < 0.5 ms |
| **Non-triggered total** | **~9 ms** | **~13 ms** |
| Cross-encoder (when triggered, ~15%) | ~30 ms | ~40–60 ms |
| **Triggered P99** | **~40 ms** | **~65 ms** |

The <15 ms guarantee holds for the **85% non-triggered path**.  
See `config.py` and the write-up for the trade-off options.

## Library Choice Rationale

| Library | Why chosen |
|---|---|
| `torch` | Standard DL training framework; replaced by ONNX Runtime at inference |
| `transformers` | Provides BGE-small model + tokenizer; well-maintained HuggingFace ecosystem |
| `sentence-transformers` | Used only for cross-encoder; cleaner API than raw transformers for cross-encoder scoring |
| `cleanlab` | Best open-source implementation of Confident Learning for silver-label noise detection |
| `sklearn.covariance.LedoitWolf` | Analytically optimal shrinkage estimator; solves the singular-matrix problem without hyperparameter tuning |
| `onnxruntime` | 3–5× faster than PyTorch CPU inference via kernel fusion; standard production choice for CPU inference |
| `onnx` | ONNX graph verifier; ensures exported model is well-formed before deployment |
| `scipy.optimize.minimize_scalar` | Smooth, bounded 1-D optimisation for temperature T* |
| `pandas` | CSV I/O, groupby operations for per-class noise analysis |
| `seaborn` | Nicer confusion matrix heatmaps |
| `accelerate` | Seamless CPU/GPU placement without code branching |

## Troubleshooting

**`FileNotFoundError: taxonomy_v1.json`**  
Ensure `data/taxonomy_v1.json` exists. The pipeline uses it as the canonical  
ground truth — it cannot run without it.

**`FileNotFoundError: best_checkpoint.pt`**  
Run `python -m train` before `python -m eval`.

**`FileNotFoundError: model.onnx`**  
Run `python -m eval` before `python -m predict`.

**OOM during training**  
Reduce `BATCH_SIZE` in `config.py` to 32 or 16.

**Cleanlab cross-validation is slow**  
Reduce `CLEANLAB_CV_FOLDS` in `config.py` to 3 for a faster (less accurate) run.

**Cross-encoder not found**  
`sentence-transformers` will auto-download `cross-encoder/ms-marco-MiniLM-L-6-v2`  
on first use. Ensure internet access or pre-download it.
